# 文書規律

- docs/ 配下は日本語 (保守者向けの内部文書)。文体は簡潔な断定調。
- **現在形の不変条件として書く。**書かないもの: 日付 / Phase 番号 / 「以前は」「当初は」 /
  コミットハッシュ / CI run ID / 実施記録 / レビューの経緯 (「〜が指摘された」「〜で直した」) /
  絵文字のステータス。
- **「なぜ」は必ず残す。**「X すると Y が壊れる」「実測では Z だった (環境条件付き)」型の
  警告と根拠が文書の存在理由である。手順だけ残して理由を消すと、次に同じ判断をやり直す。
- 参照書式は `docs/DESIGN.md §N` または `docs/DESIGN.md A19` (所見 ID)。
  節番号と所見 ID (A/B/C/D/L/S — 台帳は docs/DESIGN.md §13) は安定アンカーであり、
  コード・テスト・lint の失敗メッセージ・他文書から参照されるので付け替えない。
- 正典は 1 か所に置き、他所からは参照する。同じ判断を 2 か所に書くと必ずずれる
  (T1〜T6 と K/M は docs/TESTING.md、ローカライズは docs/LOCALIZATION.md が正)。
- **公開 API の XML doc は英語必須** (CI がゲートする)。**実装内部のコメントは日本語のまま** —
  保守者向けであり、判断の記録として価値がある (docs/LOCALIZATION.md §1)。
