# テスト規律

層の選び方 (定義の正は docs/TESTING.md §1):

- **T1** — 純ロジック。GUI 由来のロジックは Presenter / `OverlayGeometry` としてここへ
  引き下ろす。画面に出さないと再現しないものは置けない
- **T3** — 実 UIA。プロバイダーの挙動そのものが論点のものだけ。擬似入力を使わず、
  stdin のコマンドで対象アプリの UI を変化させる
- **T4** — ピッカーの UI。窓を画面に出さないと再現しないものだけ。UIA のコントロール
  パターンで駆動し、入力の配送は主張しない
- **T5** — 合成入力。低レベルフックと `WM_NCHITTEST` は実際に入力を起こさないと通らない。
  入力の配送を確かめたいときだけここへ来る (解禁 4 条件は docs/TESTING.md §3)

規律:

- **検出力を示せないテストは書かない。**入れる前に意図的な退行で実際に落とし、
  落ちなければ入れない。
- **ネガティブコントロール必須。**T3/T4/T5 の各シナリオに「わざと壊した条件で確実に
  失敗する」対を置く。前提が崩れたら時間切れではなく理由の付いた失敗で落とす。
- **合成入力は `tests/UiaTrigger.Input.Tests` のみ。**`keybd_event` / `mouse_event` /
  `PostMessage` / `SendMessage` の 4 語は入力スタックを迂回するので `tests/**` で全面禁止
  (T5 も例外ではない)。lint が**文字列として**検出するため、テストのコメントに書くだけでも
  落ちる。理由と政策は docs/TESTING.md §3。
- **既知の不安定テスト 3 件は docs/TESTING.md §5。**落ちたら本文を取る (`-v q` を付けない)。
  連続で通っても「直った」と書かない — 名前と落ち方を §5 に記録して追う。
